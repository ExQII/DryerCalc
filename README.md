# DryerCalc v1.9.3 — расчёт и контроль сушки зерна на шахтной зерносушилке

Программа для Windows 10/11 (64 бит), работает **без интернета**. Считает, сколько проходов и часов нужно,
чтобы высушить партию с W₀ до Wк, какую разгрузку D ставить; по ходу сушки подсказывает D по свежим пробам
журнала; ведёт учёт партий (весовая, топливо, тонно-проценты, отчёты), очередь сушки, погоду и поправку
влагомера; проверяет точность модели на ваших же данных. Подогнана под бумажный журнал сушильщиков
(страницы 18–25.10.2026) и таблицу пересчёта «разгрузка D → производительность».

## Установка и запуск

Два варианта, выбирайте любой — данные у них общие:

* **DryerCalc_Setup.exe** — установщик. Ставит программу в папку пользователя (права администратора не нужны),
  создаёт ярлыки на рабочем столе и в меню «Пуск», запускается за 1–3 секунды. Удаление — «Параметры →
  Приложения» или ярлык «Удалить DryerCalc» в меню «Пуск».
* **DryerCalc.exe** — переносная версия одним файлом: скопировать куда угодно (флешка, рабочий стол) и запустить.
  Первый запуск 5–20 секунд: файл распаковывает себя во временную папку.

Интернет не нужен ни для установки, ни для работы. Перенос на компьютер в хозяйстве — на флешке.

* Windows может показать синее окно SmartScreen «Windows защитила ваш компьютер» — файл не подписан
  цифровой подписью. «Подробнее» → «Выполнить в любом случае».
* Все данные (журнал, погода, партии, очередь, пары влагомера, настройки) — в одном файле
  `%APPDATA%\DryerCalc\dryer.db`. Раз в сутки при запуске программа сама кладёт копию в
  `%APPDATA%\DryerCalc\backup` (хранятся последние 14). Ручная копия на флешку и восстановление —
  раздел «Настройки сушилки» → «Резервные копии».
* Обновление: установить/скопировать новую версию поверх старой — данные и откалиброванная модель
  сохраняются, старая база дополняется новыми таблицами автоматически.
* Если что-то сломается, подробности попадут в `%APPDATA%\DryerCalc\error.log`.

**Инструкция для пользователя** (для тех, кто видит программу впервые) — раздел «Справка» → «Инструкция для
пользователя», после установки — «Пуск» → DryerCalc → «Инструкция DryerCalc», исходник — `docs/manual_ru.txt`.
Этот файл — техническое описание: что внутри моделей и как они проверены.

**2. Натура зерна** (`model.set_natura`, `model.natura_k`; поле «Натура зерна» в «Настройках сушилки»).
Таблица Q(D) и вместимость шахты записаны для натуры `DryerParams.natura` (стартовая — 650 г/л, лист пересчёта

трогаются — расход влаги свойство сушилки, поэтому на более тяжёлом зерне тот же D даёт меньший съём (и наоборот);
калибровка сохраняется. `natura_log` хранит, с какого момента действует каждое значение: строки журнала, записанные
раньше, считаются со своей натурой — «выгружено» прошлых проходов и наблюдения калибровки не меняются
(`natura_k(p)(dt)` в `observe_all`, `journal_summary`, `live_state`, `batch_meter_points`). Ограничение: для
прежних строк физическая модель считает время в шахте по нынешней вместимости (ошибка — отношение натур).
Культуры: стартовая модель — натура культуры к натуре, для которой записана Q(D) кукурузы (было — к 700 кг/м³
по НТП): пшеница 750, рапс 650, подсолнечник 350, соя 720 г/л; у сохранённых до 1.9.2 моделей культур натура —
из профиля.

**3. Номер прохода: журнал главнее счёта по рециркуляциям** (`calibration.prepare`, `LABEL_FROM`,
`regime.journal_carry`). После рециркуляции и новой подачи программа начинает следующий проход; быстрый ввод
теперь сам предлагает его номер в поле «Проход» (раньше переносил прежний, и номер «отставал»). Если в строках
после события вписан прежний номер — это исправление человеком: проход тот же, строки «нового» прохода
возвращаются в прежний, «выгружено» и средняя силоса считаются с его начала. Строка самого события не в счёт
(её номер вписан до события), пустая клетка — не исправление. Правило действует для строк журнала не раньше
первого запуска 1.9.2 на этой базе (`settings.pass_label_from`): в прежних строках номер после рециркуляции
просто не меняли, и они разбираются как раньше.

## Что нового в v1.9.1

**Выключенные горелки не заканчивают проход — конец прохода только рециркуляция** (`calibration.prepare`).

Было: слово «охлаждение» в примечании ставило `ended` — следующая подача («Запуск», «сушим с N с.») или перерыв
больше 1,5 ч начинали новый проход, а `end_kind = "cool"` объявлял партию высушенной. Горелки иногда выключают
посреди прохода при идущей подаче — проход резался надвое, «выгружено» и средняя силоса считались с нуля.

Стало:
- `burner_off` — горелки выключены: примечание «охлаждение» / «откл. т.б.» **или обе уставки блоков стали 0**
  (в проходе, где уже сушили; набор сушилки и прогрев с нулевыми уставками — не то). Включены — «запуск» /
  «вкл. т.б.» **или уставка снова выше нуля**. Сушки нет: в калибровку и «Точность модели» эти строки не идут.
- Проход не заканчивается: `ended` ставит только рециркуляция после сушки (и, как раньше, смена «Партии» /
  «Прохода» и рециркуляция через силос начинают новый).
- Подача при выключенных горелках идёт в силос: такие часы входят в «выгружено», пробы выхода — в среднюю
  приёмного силоса и в среднюю прохода (`batches.journal_summary`, `live_state`, `analysis.batch_meter_points`).
- `cool` — горелки выключены после рециркуляции (подача закончена): `end_kind = "cool"`, конец партии — как было.
- «Текущий проход» без рециркуляции пишет «Горелки выключены — сушки нет, проход продолжается».

Журналы ноября и октября разбираются так же, как раньше (в них охлаждение всегда после рециркуляции): те же
проходы, «выгружено» и калибровка. Следствие для ведения журнала: конец прохода без строки «рециркуляция»
(сразу «охлаждение») программа концом прохода больше не считает — см. «Правила», п. 6.5.

## Что нового в v1.9.0

Пять доработок про данные на входе — модель не менялась.

**1. Проверка пробы при вводе** (`app/entry.py`, `sample_doubt`). Новая проба входа / выхода сравнивается с
последними пятью пробами того же потока (не дальше 3 ч назад, не через событие в примечании и не через смену
партии / прохода). Ушла от их медианы больше чем на max(2,5 п.п.; 5 разбросов) или вне 4–45 % — вопрос «Исправлю /
Записать как есть». Повтор журналов: ноябрь (576 проб) — переспрошены 2 настоящие пробы, октябрь (309) — тоже 2;
подставленные опечатки на ±10 п.п. пойманы в 98–99 % случаев, на ±5 — в 89–95 %, на ±3 — в 68–75 %. У первых
двух-трёх проб потока (≈ 15 %) истории нет — проверяется только диапазон.

**2. Две пробы** (`parse_moisture`). В поля влажности быстрого ввода можно ввести две пробы через пробел или «/»
— в журнал идёт среднее (до 0,05). Пока вход выше 27 % (в пересчёте на кукурузу), под быстрым вводом напоминание
брать две пробы. Выигрыш — расчётный (шум среднего двух независимых проб в √2 раз меньше); на журнале не проверен:
двойных проб в нём ещё нет.

**3. Q(D) по весовой** (`batches.q_check`, `q_check_all`, `scale_q`). «Выгружено» за проход по журналу против массы,
которая должна была выйти: сухое вещество партии по весовой / (100 − W выхода прохода); для последнего прохода — сама
масса после сушки, если вписана. В сверку не идут проход, который ещё идёт, и проход с расхождением больше 15 %
(прошла не вся партия, журнал неполный). Поправка предлагается, когда проходов не меньше двух, они согласны в
пределах 6 %, а множитель дальше 2 % от единицы. Вместе с Q(D) на тот же множитель меняются R₀ и η — прогноз
влажности при каждом D остаётся прежним (эмпирическая модель — точно, физическая — тоже: η·τ не меняется).
На базе пользователя: партия 1100 т, проходы 2 и 3 — ×0,954 и ×0,963, общий множитель 0,958 (Q(D) завышена на 4,1 %);
первый проход (×1,56) в сверку не идёт — журнал начат позже партии.

**4. Накладные на проход по журналу** (`batches.overhead_from_journal`). Часы за проход, когда сушилка работала, а
зерно прохода из силоса не шло: набор, рециркуляция, рециркуляция через силос, работа без горелок; остановки,
перерывы длиннее 1,5 ч и охлаждение не считаются. Медиана по законченным проходам — кнопкой «По журналу: … ч» в
«Настройках сушилки». На базе пользователя: 4,8; 6,2 и 2,5 ч при настройке 1 ч. Проверка на проходах 2 и 3:
план «масса / Q + накладные» отставал от факта на 7,5 и 3,3 ч; с Q(D) × 0,958 и накладными 4,75 ч — −1,5 и +2,5 ч.

**5. Проверка пары влагомера** (`pair_doubt`). Разность «показание − после охлаждения» дальше max(1,5 п.п.;
4 разброса) от медианы остальных пар — вопрос при вводе, один раз на пару. Меньше четырёх пар — только грубая
проверка (разность больше 4 п.п., число вне 4–45 %).

## Что нового в v1.8.0

**Культуры.** Раздел «Культура» (первый в меню, только в режиме инженера): кукуруза, пшеница, рапс, подсолнечник,
соя (озимые и яровые не разделены). У каждой культуры свои журнал проб, модель, партии, очередь, пары влагомера и
поля ввода (`storage.CROP_KEYS`, ключ настроек с суффиксом `@культура`; столбец `crop` в журнале, пусто —
кукуруза). Сушилка, погода, напоминания и режим — общие. Старая база открывается как кукуруза, без миграции.

Стартовая модель культуры (`app/crops.py`), пока по ней нет своего журнала, — модель этой сушилки на кукурузе,
пересчитанная по трём правилам:

1. **Равная равновесная влажность воздуха (ERH).** Влажность культуры линейно переводится в «влажность кукурузы
   с той же ERH» по двум точкам (кукуруза 8 и 15 % при 25 °C); в этой шкале считают обе модели (`model.corn_equiv`).
   Изотермы: кукуруза, пшеница, соя — модифицированный Хендерсон, ASAE D245; рапс — модифицированный Хэлси,
   десорбция (Sun & Byrne, 1998); подсолнечник — опорные точки 8 % ↔ 65 %, 9 % ↔ 75 % RH (GRDC, 2015).
2. **Расход влаги R (т воды/ч) — свойство сушилки.** Множитель скорости — только где его дают нормы: пшеница
   ×1,6 (Инструкция № 9-3-82: производительность на кукурузе — 0,6 от пшеницы). Остальные — ×1,0.
3. **Q(D) и вместимость шахты — объёмные**: в тоннах пересчитаны отношением насыпных плотностей к кукурузе.

| Культура | Равноценно кукурузе 8 / 22 % | Скорость | Плотность, кг/м³ | Цель, % | Съём, п.п. | T зерна / агента, °C |
|---|---|---|---|---|---|---|
| Кукуруза | 8,0 / 22,0 | 1,0 | 650 (с 1.9.2; было 700) | 14 | 6 (до 10) | 75 / 75 (как было) |
| Пшеница | 9,1 / 21,3 | 1,6 | 750 | 14 | 6 | 50 / 140 |
| Рапс | 4,4 / 16,0 | 1,0 | 650 | 8 | 6 | 45 / 80 |
| Подсолнечник | 4,5 / 13,5 | 1,0 | 350 | 7 | 6 | 55 / 115 |
| Соя | 5,0 / 21,9 | 1,0 | 720 | 12 | 3 | 30 / 60 |

Пределы и съём — Инструкция № 9-3-82, табл. 1 и п. 6.3 (продовольственное зерно; рапса в таблице нет — взяты
обычные для товарных маслосемян); плотности — НТП-АПК 1.10.10.001-02, прил. Д (рапс — 650).

**Это оценка, а не калибровка, и на данных она не проверена** — журналов по этим культурам с этой сушилки нет.
Допуск скорости ±30 % (rate_sigma 0,25): планы показывают широкие интервалы. Констант тонкого слоя по культурам
для шахтной сушилки и нормативного множителя для рапса, подсолнечника и сои найти не удалось — поэтому ×1,0.
После 12 строк журнала культуры «Калибровать модель» подбирает её модель по факту, как для кукурузы. Q(D) и
вместимость в тоннах стоит сверить по весовой на первой же партии.

**Проще интерфейс.** Длинные пояснения свёрнуты и открываются нажатием на заголовок (`ui_common.Collapsible`):

  иначе «Проход закончен — идёт рециркуляция»; плитка «Конец прохода» — «подача закончена»; напоминания о конце
  прохода во время рециркуляции не приходят. Охлаждение — тоже конец партии;
* номер прохода, если его не сменили в журнале, программа считает сама по рециркуляциям («проход 2 (по
  рециркуляциям)»), партию — по досушкам; силосы подачи прохода видны в «Данных прохода и задании»;
* «закончили рециркуляцию» — теперь конец рециркуляции (раньше — слово-ловушка); «открыли люк», «переключили
  вентилятор», «снимаем пробу» больше не ловушки: подачу программа узнаёт по образцу «сушим / открыли /
  переключили … с N с.».

Для калибровки проход по-прежнему режется на участки непрерывной работы (остановка / пуск, загрузка / зачистка,
перерыв > 1,5 ч), а переключение силоса участок больше не режет: поток зерна через шахту не прерывается, и пробы
первых ≈ 3 ч после переключения тоже идут в калибровку (вход берётся по пробам до переключения). Строки
рециркуляции из калибровки исключены явно (раньше — только если рециркуляция начиналась словом «закончил…»). На
журнале октября проходы и калибровка не изменились (120 строк, ±0,44 / ±0,067 п.п., прогноз прохода ±0,051 п.п.) —
там новый проход всегда отмечен сменой «Партия» / «Проход». Правила работы (разделы 1, 5, 6, 10, 20, 21) и
инструкция (6.2, 7, 9, шпаргалка) обновлены.

* кнопка «Изменить режим…» под полями T блоков и D: время (по умолчанию — сейчас, если оно не дальше часа от

* изменение задним числом (забыли записать): окно предлагает исправить старый режим в строках после события —

  корреляция остатков по проходам). Для неподобранных коэффициентов (погода, пока её мало в журнале) — априорные
  дисперсии `calibration.PRIOR_SD`. Внутри изученного добавка 0, вне — растёт сама;
* σ_моделей = ½·max(0, |Δ_эмп − Δ_физ|/Δ_эмп − типичное расхождение на проходах журнала): если эмпирическая
  и физическая модели предсказывают сценарий по-разному сильнее обычного, значит, обе экстраполируют.
Плюс флаги «вне изученного» (D ± 2 с, T ± 2 °C, W ± 1 % от пределов журнала) в колонке «Оценка», а состав
допуска — во всплывающей подсказке и в строке состояния. На журнале-образце (W 34 → 14 %, 500 т, 60 °C,
погода 10 °C / 70 %), в «±» на 90 %:

| Сценарий | D, с | Допуск скорости | проверка / коэффициенты / модели |
|---|---|---|---|
| 1 проход | 12 | ±19 % | 8 / 0 / 17 |
| 2 прохода | 22 | ±9 % | 8 / 1 / 3 |
| 3 прохода | 49 | ±8 % | 8 / 1 / 0 |
| 4 прохода | 66 / 61 / 52 | ±8 % | 8 / 1 / 0 |

Вне изученного по T = 90 °C коэффициенты добавляют 1,8 % (1σ), при W 30 % и 90 °C — 2,7 %; погода 0 °C / 90 %
вместо изученных — 7,1 %. В отчёт калибровки добавлена строка «ДОПУСКИ» с разбросом коэффициентов, эффектом
дизайна, типичным расхождением моделей и изученными пределами. Старые сохранённые параметры без этих полей
читаются, добавок у них нет до первой калибровки.

**Средняя влажность приёмного силоса.** Цель прохода на «Сейчас» относится к средней по силосу: программа
накапливает выгруженное с начала прохода (Q·Δt, влажность — по выходному влагомеру с поправкой), учитывает
зерно в пути (lag_k·m_шахты) и ставит цель остатку
W_нужно = (W_цель·M_всего − W_вып·M_вып − W_в пути·M_в пути)/M_остаток, но не дальше «±» от цели (по умолчанию
1,0 п.п.; если остаток < 5 % прохода или < 5 т — уже поздно, цель обычная). Пример: ушло 109 т по 22,2 % при
цели 24 % (проход 368 т, 60 т в пути) → остатку нужно 25,55 %, с ограничением 25,0 % → среднее выйдет 23,7 %
(при «± 3» — 24,0 %).
Галочка и «±» — во вкладке «Сейчас (по факту)», в таблице — колонка «Среднее по силосу, %».

**Поправка выходного влагомера по партиям.** Второй источник, кроме пар «влагомер — лаборатория»: для каждой
партии с лабораторной W после охлаждения программа берёт последний проход партии, взвешенное по массе
показание выходного влагомера (строки с горелкой, без рецикла) и сравнивает с лабораторией с учётом k_w, k_t.
Оценки объединяются с парами по обратным дисперсиям (у партии σ = max(sd, 0,15)/√n при n ≥ 3, иначе 0,4/√n);
если пары и партии расходятся больше чем на 2σ — предупреждение вместо молчаливого усреднения. На журнале-
образце: 5 пар дают a = +0,82 ± 0,09, три партии (лаборатория ниже влагомера на 0,95 / 0,70 / 1,10) — +0,92 ± 0,12,
вместе +0,85 ± 0,07 (вес партий 35 %); если партии показывают +2,0, а пары +0,8 — программа не усредняет молча, а
предупреждает: «расходятся на 1,21 п.п. — больше случайного». Галочка «Учитывать партии» — во вкладке
«Погода и влагомер».

**Мелочи.** Подписи осей графиков по центру, заголовок не обрезается (ширина подбирается по реальной отрисовке).

## Что нового в v0.5.0

1. **План опытов** («Проверка и опыты» → «План опытов»): какие D и T блоков поставить на следующих проходах,
   чтобы модель быстрее уточнялась. Балл кандидата = новизна режима (расстояние от изученных проходов в
   координатах D/10 с, T/10 °C, W/5 п.п. — идея D-оптимального плана) × (1 + расхождение моделей в единицах

   на лимит съёма по обеим моделям (берётся худшая), предел T блоков и T зерна; по умолчанию меняется один фактор.
2. **Рециркуляция** (вкладка «Рециркуляция»): досушка содержимого сушилки по кругу. Эмпирическая модель:
   du/dt = −R(w)/DM (u — влагосодержание на с.в.), физическая — кривая тонкого слоя по накопленному времени
   в горячей зоне η·f_hot·t. В журнале строки после «рециркуляция» не считаются выгрузкой из силоса,
   строки после «охлаждение»/«откл. т.б.» не используются в калибровке.
3. **Допуск прогнозов**: время сценариев, конец партии на «Сейчас», рециркуляция — с 90 %-интервалом:
   скорость сушки ×(1 ± 1,645·σ), σ — относительная СКО честных прогнозов съёма на журнале (на октябре 4,5 %).
4. **Качество зерна в партиях** (трещиноватость, битое, натура, всхожесть, назначение) и подвкладка
   «Качество и режим»: связь с макс. съёмом за проход, T блоков, T зерна (оценивается с 5 партий).
5. **Полная поправка влагомера**: a + k_w·(W − 20) + k_t·(T зерна − 30); наклоны подбираются по парам проб,
   только если пар достаточно (≥ 10 / ≥ 12 с T) и эффект больше двух стандартных ошибок.
6. **Тепловой КПД по топливу**: теплота сгорания → МДж на 1 кг испарённой воды и КПД = 2,5 МДж/кг / удельный
   расход — в карточке партии, отчётах и сводке сезона.
7. **Напоминания сушильщику**: «пора внести пробу», «проход скоро закончится», «выход ушёл от цели» —

   (по журналу, после очереди или вручную), три варианта массы из допуска, ёмкости, срок хранения сырого зерна.
4. **Текущий проход** — см. ниже.
5. **Журнал проб.** Строка быстрого ввода, меню «Импорт и бланки» (импорт CSV/XLSX, шаблон, пример, бланк PDF),
   правка таблицы, «Калибровать модель» (калибрует обе модели сразу, показывает ошибки по строкам и по проходам).
6. **Досушка.** Рециркуляция: сколько часов досушивать содержимое шахты.
7. **Партии и очередь.** Учёт партий и отчёты; смешивание и очередь сушки.
8. **Погода и влагомер.** Таблица погоды, импорт, графики; пары проб влагомера и поправка.
9. **Точность модели.** Прогноз против факта по проходам, сравнение моделей, дрейф, вес свежих данных,
   автокалибровка; план опытов.
10. **Настройки сушилки.** Таблица Q(D), вместимость, накладные, поправка влагомера, лаг, выбор модели,
   параметры обеих моделей, температура зерна и пределы, напоминания, резервные копии. Баннер в «Плане сушки
   партии»: золотистый — стартовая калибровка, зелёный — откалибровано по журналу, красноватый — изменено вручную.
11. **Справка** — инструкция, правила работы и этот текст.

## Раздел «Текущий проход»

1. Вносите пробы в журнал как обычно (удобнее строкой быстрого ввода: время подставляется само).
2. На вкладке «Данные прохода и задание» задайте массу на входе текущего прохода и желаемую влажность на выходе
   этого прохода (после охлаждения; рядом показано, сколько при этом покажет выходной влагомер).
3. Программа берёт последний участок журнала (проход), считает, сколько уже выгружено (Σ Q(D)·Δt), и показывает:
   * что сейчас выходит при текущем D и какое D нужно для цели (таблица вариантов D рядом; можно проверить своё D);
   * **через сколько часов изменение D станет видно на выходе**: зерно, уже находящееся в шахте, выходит
     со старой скоростью; τ = m_сушилки / Q(D) (при D = 35 около 3,3 ч). Менять D чаще, чем раз в τ/2,
     бессмысленно — результат прошлого изменения ещё не виден;
   * когда закончится проход, сколько ещё проходов (с какими D) нужно до Wк и когда закончится партия.
4. «Поправка по последним замерам»: модель сравнивается с 6 последними (≈ 3 ч) замерами выхода этого прохода,
   средняя ошибка с ослаблением n/(n+3) прибавляется к прогнозу. С 1.5.3 по умолчанию выключена: на журналах
   октября и ноября 2026 прогноз без неё точнее (±0,82 против ±0,87 и ±0,41 против ±0,47 п.п.).

## Погода без интернета

Источники (любые, можно смешивать — замеры с одинаковым временем заменяются новыми):

* **Замеры у сушилки** термометром-гигрометром: «Погода и влагомер» → «Добавить замер», впишите T и RH.
  Можно писать и прямо в журнал (колонки «T наружная», «RH наружная») и в бумажный бланк.
* **Логгер** температуры/влажности (выгрузка CSV/XLSX): колонки даты-времени, температуры и влажности
  распознаются по названиям («Время», «Дата» + «Время», «Температура», «Влажность», «Temperature», «Humidity»).
* **Архив rp5.ru** — на любом компьютере с интернетом: rp5.ru → ближайшая метеостанция → «Архив погоды» →
  период → «Скачать» в формате CSV (кодировка любая) → файл `.csv.gz` на флешку → «Импорт файла…»
  (распаковывать не нужно). Берутся колонки «T» и «U».
* **Open-Meteo** — open-meteo.com → Historical Weather: координаты хозяйства, почасовые «Temperature (2 m)» и
  «Relative Humidity (2 m)», часовой пояс «auto» → «Download CSV».

Подстановка в журнал: линейная интерполяция между замерами не дальше 6 ч друг от друга, иначе ближайший замер
в пределах 3 ч, иначе ничего (берутся опорные 10 °C / 70 %). Проверьте, что время в файле местное, как в журнале.

## Поправка выходного влагомера

Выходной влагомер меряет горячее зерно и может показывать иначе, чем та же проба после охлаждения. Модель считает
съём по «истинной» влажности = показание − поправка; поправка входит прямо в рассчитанный съём, и 0,8 п.п. против
нуля меняют расход влаги R примерно на 10–15 %. С 1.3 по умолчанию поправки нет: только внесённая по парам проб
или вручную (прежние +0,8 п.п. по четырём пробам с фото журнала октября убраны). Влагомер откалиброван на сухое
зерно, поэтому ошибка зависит от влажности — набирайте пары на разных проходах, тогда виден наклон k_w. Набирайте пары «показание на выходе / та же проба после охлаждения или в лаборатории»: программа
считает среднее, 95 %-интервал (по Стьюденту) и отсеивает выбросы. Точность ≈ 2·разброс/√n: при разбросе пар
±1 п.п. (как в четырёх октябрьских) 20 пар дают ±0,45 п.п., 50 пар — ±0,3. Аккуратный отбор (одна и та же проба,
один прибор после охлаждения) уменьшает разброс быстрее, чем число пар. После «Применить поправку в модель»
перекалибруйте модель по журналу.

## Партии: весовая, топливо, тонно-проценты, отчёты

* Строка — партия: начало/конец (связь с журналом), массы до и после сушки (весовая), влажность до и после
  (лаборатория или после охлаждения), отходы, топливо за партию, цена топлива. «Создать из журнала» — черновики
  по колонке «Партия».
* **Сухое вещество сохраняется:** m_вых = (m_вх − отходы)·(100 − W_вх)/(100 − W_вых). Расхождение с весовой и
  «влажность по массам» = 100 − (m_вх − отходы)·(100 − W_вх)/m_вых показывают, врут ли влагомеры (или есть
  неучтённые потери). По одной партии их не разделить; по сезону виден устойчивый сдвиг (сводка внизу).
* **Тонно-проценты** = (m_вх − отходы)·(W_вх − W_вых). **Удельный расход топлива** — на 1 т испарённой воды;
  кнопка «Перенести расход топлива в план» переносит его в раздел «План сушки партии».
* Отчёт по партии — PDF и Excel (проходы по журналу, сверка, вода, топливо, деньги); сводка сезона — Excel.

## Очередь и смешивание

* **Смешивание:** W смеси = Σ m·W / Σ m (вода складывается). Если части отличаются больше чем на 6 п.п.,
  программа предупредит: сухие зёрна пересохнут, сырые недосохнут.
* **Очередь:** партии сушатся по порядку, каждая занимает сушилку на все свои проходы. Метод «по модели» —
  рекомендованный сценарий (минимум проходов в лимите), «по производительности» — заданный Q и лимит съёма.
  «Готова к сушке» — партия не начнётся раньше. Диаграмма: проходы чередуются оттенками, серое — охлаждение.

## Как устроены модели

**Общее.** Вся партия M проходит через сушилку, ложится в силос, затем следующий проход. Выгрузка Q = Q(D),
время прохода = масса выгруженного зерна / Q. Баланс влаги (w — % на сырую массу):
**R = Q · (w_вх − w_вых) / (100 − w_вх)**, т воды/ч. Выход в момент t относится к зерну, вошедшему на
τ = m_сушилки/Q раньше; калибровка сопоставляет выход со входом на τ раньше. Плюс накладные ≈ 1 ч на проход и
финальное охлаждение на D = 100 (масса / 52 т/ч).

**Эмпирическая** (основная):
`R = R_ref · ((w_ср − w_eq)/(w_ref − w_eq))^b_w · ((T − 10)/(T_ref − 10))^b_dt · e^(b_нар·(T_нар − 10)/10) · e^(b_rh·(RH − 70)/30)`.
R_ref и показатели подбираются регуляризованной регрессией по журналу (показатели — только при ≥ 12 строках и
разбросе данных; b_rh — только когда RH есть во всех строках; b_нар не подбирается — физическая оценка, см. 1.7.3).

**Физическая** (вторая): зерно в горячей зоне (доля f_hot ≈ 0,8 объёма) находится t_h = f_hot·m_сушилки/Q.
Кинетика зерна в тонком слое — коэффициенты по умолчанию (Thompson, Peart, Foster, 1968, Trans. ASAE 11(4): 582–586):
`t = A·ln MR + B·(ln MR)²`, A = −1,862 + 0,00488·T, B = 427,4·e^(−0,033·T) (T в °F, t в ч),
MR = (M − Me)/(M0 − Me); равновесная влажность Me — модифицированное уравнение Хендерсона из той же работы,
RH агента — психрометрически (нагрев наружного воздуха при постоянном влагосодержании). Эффективное время
t_eff = η·t_h·k_нар: η — КПД слоя (калибруется), k_нар — поправка на прогрев холодного зерна (тепло делится между
прогревом и испарением).

**Температура зерна** ≈ a + b·T_блоков + c·(W_вх − 22); по журналу октября 5,1 + 0,42·T − 0,46·(W − 22),
разброс ±2,3 °C (влажное зерно холоднее — испарение). Кнопка «Подобрать a, b, c по журналу». Пределы T блоков и
T зерна задайте сами по инструкции для вашего назначения зерна (семенное, продовольственное, фуражное) —
сценарии, которые их превышают, помечаются красным.

## Как проверена модель (журнал 18–25.10.2026, 4 прохода)

| Ошибка съёма за проход, п.п. | эмпирическая | физическая |
|---|---|---|
| описание известных данных (текущая калибровка) | ±0,14 | ±0,51 |
| прогноз прохода только по предыдущим (как в жизни, 3 прохода) | ±0,31 | ±0,65 |
| прогноз исключённого прохода по трём остальным | ±0,25 | ±0,64 |

Эмпирическая точнее на этих данных. Сушилка оказалась заметно менее чувствительной к T блоков, чем тонкий слой
(проход при 48 °C снял почти столько же, сколько при 73 °C), поэтому физическая модель с одним η ошибается
сильнее. Её польза — независимая вторая оценка за пределами журнала. Вкладка «Проверка модели» пересчитывает
эту таблицу на ваших данных по мере накопления журнала.

По строкам w_вых ошибка ±0,5 п.п. (шум влагомера, замеры раз в 30 мин). Длительность проходов: по журналу
проход при D ≈ 35 идёт 20–22 ч, m/Q даёт 19–22 ч.

## Ограничения

* Четыре прохода — малая выборка: W вх 18–33 %, D 35–43, блоки 48–73 °C. За пределами — экстраполяция
  (смотрите колонку «Вторая модель»).
* Влагомеры показывают «Hi» выше ≈ 35–40 %; такие строки в калибровку не годятся.
* Влияние погоды (b_нар = 0,03, b_rh = −0,15) оценено по физике, а не подобрано: b_нар по журналу не
  подбирается (1.7.3), b_rh — только при RH во всех строках. Погоду записывайте — она входит в прогноз.
* Поправки выходного влагомера по умолчанию нет — копите пары проб на разных проходах.
* κ (доля перепада температур в слое) у физической модели не калибруется: на журнале октября её подбор давал
  переобучение (лучше описание, хуже прогноз). По умолчанию κ = 1.
* Модель одной зоны: не разделяет нагрев и охлаждение, не учитывает отлёжку в силосе и частичный последний проход.
* Первый проход партии (влажное зерно 29,9 → 22,9 %) в пример построчно не вошёл; часть строк 21.10 оцифрована
  приблизительно — сверьте с оригиналом.
* Нормы нагрева зерна в программу не заложены — пределы задаёт пользователь.
* Файлы не подписаны цифровой подписью: возможны предупреждения SmartScreen и антивируса (типично для программ,
  собранных PyInstaller). Сертификат подписи платный и для программы «для своих» обычно не нужен.
